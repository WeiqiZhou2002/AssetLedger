# 产品与工程决策

本文只记录当前有效的规则，是产品与工程决策的首要依据。
实现约定与检查命令见 [AGENTS.md](../AGENTS.md)，使用与自托管说明见 [README.md](../README.md)。

## 产品边界

- 单人自托管账簿，没有公开注册入口；业务数据始终按登录用户隔离。
- 界面使用简体中文，账户、机构、币种和积分项目保留官方名称。
- 主要页面为总览、流水、账户、导入与同步、卡权益、积分里程、投资和设置。
- 总览回答当前资产、负债、净资产以及本月收入和支出。
- 账户余额、记账流水与积分记录分别建模，不互相冒充数据来源。
- 移动端与 PWA 使用相同业务规则；所有敏感操作由服务端校验。
- 默认初始化必要目录和设置，不自动建立所有者的积分账户。
- 演示种子必须显式启用，使用独立演示用户与合成资料。

## 会计模型

- 账本由 journal entries 与 postings 组成，分录金额使用带符号的十进制数。
- 借方为正，贷方为负；每笔已确认流水在每种币种内的分录之和必须为零。
- 账户账面余额为该账户已确认 postings 的代数和。
- 信用卡欠款和借款负债为负，溢缴款为正；不得截断透支或溢缴的符号。
- 跨币种交易通过各币种的 `fx_clearing` 科目分别平衡，不能跨币种直接相加。
- 真实资产类型为现金、券商现金、证券、应收款和预付款。
- 真实负债类型为信用卡与借款；完整枚举以 `lib/ledger/constants.ts` 和数据库 schema 为准。
- 收入、支出、期初权益、外汇清算、转账清算及兼容调整科目为系统科目。
- 支出按 expense 分录净额计算；退款抵减支出。
- 收入按 income 分录计算，不仅依据流水的类型标签。
- 内部转账、还卡、投资本金、借款本金及作为资产的预付款不计消费。
- 手续费及其他真实收支分录仍按对应科目计入统计。
- 购物组仅聚合关联流水，不生成额外分录或重复金额。
- 已确认流水的金额、币种和账户等记账内容只能作废后替换，并记录审计。
- 商户、分类和备注等非金额信息可按服务规则原位更正，并记录审计。
- 草稿不参与余额与收支统计；普通流水列表默认隐藏作废项，仍可显式查询。
- 数据重置和删除全部个人数据是需预览或确认的独立删除流程，不属于日常金额编辑。

## 总览、估值与汇率

- 当前净资产等于资产合计减负债合计，覆盖所有币种并折算为所有者的基准币种。
- 资产包含现金、券商现金和证券；应收款与预付款遵循 `financial_inclusion`。
- 信用卡和借款列入负债，展示时转换为负债口径，仍保留溢缴等反向余额。
- `cash_like_inclusion` 和其他内部统计范围不替代当前总览的资产、负债口径。
- 每账户优先使用截至查询日的最新已发布余额观察，观察日期可以不同。
- 没有观察时，仅已有已确认期初的非证券账户可以使用账本余额推算。
- 证券必须有市值观察，不能把证券成本分录当作市场价值。
- 缺余额或汇率的账户明确排除并提示；不能以零值掩盖缺失资料。
- 既有账户组汇总不能猜分为成员余额，也不能混合资产与负债后当作单一余额。
- 汇率表示每单位基准货币对应的报价货币数量；原币折算基准币使用除法。
- 余额观察保存冻结汇率；汇率陈旧与余额陈旧分别提示，不静默改写历史观察。
- 本月收支入口使用当前月份；收支明细可切换月份及入账日、发生日口径。
- 明细按分类和真实贡献收支的分录下钻，退款在支出明细中为负。

## 余额观察与提醒

- Plaid 同步与手工单账户更新都记录余额观察，不自动创建流水或期初分录。
- 首次同步当天就是余额记录的起点，不要求先完成期初余额工作流。
- 账户页及银行映射表单不提供期初创建入口。
- 既有显式 `opening_balance` 分录仍有效；兼容服务及补导、重置中的既有期初处理保留。
- 账户卡片主金额是最新个别账户余额；组汇总不能冒充个别账户观察。
- 手工更新只允许启用、非系统、没有启用 Plaid 映射的真实账户。
- Plaid 证券映射同样阻止手工更新；证券账户录入市值，其余账户录入余额。
- 日期不得晚于所有者时区的今天；金额输入保留十进制字符串及账户原币。
- 外币观察缺少可用汇率时不能发布；可在更新时提供所需汇率。
- 新账户的手工余额提醒默认每 7 天，可设为 1、3、7、14、30 天或关闭。
- 仅手工账户参与提醒，关闭以空值表示，不影响 Plaid 的同步调度。
- 没有观察，或最新观察日期严格早于今天减提醒天数，才标为待更新。
- 账户详情显示余额来源和时间，并提供最近流水及完整流水入口。

## 净资产回溯

- 非证券账户以余额观察为锚点，结合已确认流水回推每日余额。
- 回溯交易日期使用入账日，缺失时使用发生日；开户前视为已知零。
- 证券、贷款及缺少交易流的账户按相应余额或市值观察延用，不能虚构交易。
- 覆盖前的延用值、汇率回退及不完整覆盖都标记为估计，曲线以虚线区分。
- 无余额依据或任何可换算汇率的账户全程排除，避免账户集合变化制造跳变。
- 每日换汇优先使用不晚于当日的目录汇率，再用锚点冻结或最早可用汇率并标记估计。
- 历史完整观察点保留独立的冻结汇率；回溯曲线不代表已经逐笔核对的账本。

## 转账与还卡

- 已匹配的银行转账以两条清算腿关联，各腿保留自身账户、日期与来源证据。
- 每条腿通过 `transfer_clearing` 平衡；有效配对的两侧清算金额相互抵消。
- 配对必须来自不同账户、币种相同、金额反向等额，并满足账户类型组合规则。
- 现金流向信用卡的正入账识别为还卡；其他有效组合按转账处理。
- 自动匹配默认比较发生日或入账日的最近距离，窗口为 5 天。
- 机构别名、完整五位尾号或独立四位尾号、明确转账词和上游分类提供匹配信号。
- 账户昵称和通用产品词不能单独充当机构身份信号。
- 双方须互为唯一最强候选；同额本身不足以把普通消费或收入变成转账。
- 所有者编辑、已有匹配、上游待审核、权益与受保护退款等状态阻止自动转换。
- 未匹配的自动交易按方向记为收入或支出，普通卡退款仍按退款处理。
- 后续发现有效对方时，通过作废替换转换为清算腿，保留证据及变更链。
- 人工建立的贷款清算腿等不能转换为普通收支的情形保留专门规则。
- 现金账户存现按收入处理；现金账户 cash advance 出账按支出处理。
- Zelle 先寻找有相应信号的自有账户对方，不能唯一配对时保留收支。
- 流水详情支持手工配对、指定对方账户和取消匹配；手工候选窗口为 7 天。
- 指定对方账户需校验同一套配对规则，避免重复生成对侧流水。
- 「可能的转账」队列独立于 Plaid 开关，覆盖不同导入来源的合格已确认流水。
- 队列检查近 365 天、日期相距至多 5 天的反向等额组合，供所有者确认或拒绝。
- 期初、余额调整、权益、关联退款、购物组及已被退款引用的消费等不进入该队列。
- 两侧均为清算腿的组合沿用待匹配转账入口，避免重复展示建议。
- 确认、拒绝和指定账户使用稳定 provider 身份或替换链根保存匹配记忆。
- 记忆跨作废替换、重置与重新导入保留，确认与拒绝以最新操作为准。
- 自动流程先恢复显式选择，再运行启发式匹配；恢复仍校验配对类型与上游审核状态。
- 显式取消匹配清除对应记忆；自动解除和重置不等于所有者撤销选择。
- 流水列表将匹配双方合为一行 From → To，筛选和详情仍可追溯两侧。

## Plaid 同步

- Plaid 默认关闭；启用后按环境配置凭据，通过 Link 授权并完成账户映射。
- 新连接默认自动入账，可关闭并切回逐行审核。
- 自动入账只处理满足映射、范围及状态要求的交易；待审核项不能被静默跳过。
- 未被所有者修改的自动记录可按规则接受上游变更；受保护或冲突记录保留审核入口。
- 已确认金额的上游更正也使用作废替换；上游删除不得绕过保护检查。
- 默认每 12 小时调度，也可手动同步；调度间隔不保证银行源数据同频刷新。
- `PLAID_HISTORY_START` 留空时，以所有者本地今天减默认 90 天确定起点。
- `PLAID_DAYS_REQUESTED` 可配置；固定历史起点与请求天数受最多 730 天限制。
- 改变配置不会修改既有 Item 的历史请求深度或已保存导入日期。
- 补导只重放 Plaid 实际持有的历史，不能通过补导或重置扩展 Item 的历史窗口。
- 更早流水可用 PDF 或 CSV 补充；已有连接需要恢复授权时优先重新授权。
- Link 选择已连接机构时默认拦截，提供重新授权已有连接或明确添加另一套登录的选择；覆盖只限本次 Link 会话。
- 服务端在交换 public token 前按所有者、环境和未撤销机构检查重复；未明确覆盖时返回 409，覆盖操作仅审计实体 ID。
- 重复检查使用独立读取，Plaid exchange 在数据库事务外执行，随后立即在事务内保存加密令牌和审计；允许同时连接同一机构时的检查竞态。
- Trial 删除 Item 不返还名额；页面计数包括本地保留的已撤销和迁入连接，最终额度以 Plaid 为准。
- 「导入与同步 → 自动同步」底部提供默认折叠的「迁移银行连接」；设置银行旧地址继续跳转到同步页。
- 连接迁移独立于个人数据导出，导出和导入均需新 TOTP（启用时）或当前密码，并共用现有限流和来源校验。
- 迁移口令为 12–1024 字符，导出时不得与登录密码相同；下载和响应禁止缓存，不将凭据渲染到页面。
- 迁移文件使用 Argon2id（16 字节随机盐、65536 KiB、3 次、并行度 1、32 字节原始密钥）及 AES-256-GCM（12 字节随机 IV）；AAD 使用固定键顺序的 JSON，认证 format、version、environment、createdAt 及完整 kdf 对象。
- 仅迁移当前环境未撤销连接的 Item ID、令牌、机构、产品、自动入账与历史范围设置及 Plaid 账户元数据；不携带账本账户 ID、游标、交易或余额。
- 导入要求启用 Plaid、相同环境和匹配的开发者凭据；文件不超过 256 KB、最多 25 个连接，校验 KDF 参数上限后才解密。
- 导入先跳过已有 Item，再通过 Plaid 验证令牌与 Item ID；无效或需重新授权的令牌逐项失败，本实例已有撤销记录不得复活。
- 导入不交换 public token、不创建 Item、不撤销 Item；令牌改用目标实例独立用途密钥加密，保留历史范围，游标及映射确认清空。
- 导入账户以 Plaid 验证结果为准，文件元数据仅作提示；复用现有账户映射流程，由所有者确认后同步。
- 迁移审计仅记录连接实体 ID 和计数，不记录 Item ID、令牌、机构或账户资料；个人导出及删除全部数据行为不变。
- 加密迁移文件仍视为银行数据访问钥匙，导入后删除文件并停用旧实例同步；旧实例删除连接或全部数据会撤销共享 Item，导致新实例失效。
- 同步保存缓存余额及可用投资持仓市值，不调用付费实时余额接口，不导入投资交易。
- 核心现金仓位的内部申赎不计流水；真实股息收入按收入处理。
- 重置必须先预览并明确确认；命令行默认仅预览，显式执行才修改数据。
- 重置保留银行连接、令牌、映射和自动入账设置，不撤销银行授权。
- 删除范围限于所选连接创建的 Plaid 记录及其替换链，关联证据不能扩大归属范围。
- 手工及文件导入流水、积分和设置保留；跨范围关联需清理而非误删另一侧。
- Plaid 余额观察默认保留，需显式选择才清除对应观察；手工观察不受影响。
- 重置保留商户分类记忆和转账选择，更新任务代次，避免旧任务继续写入。
- 重置恢复导出不含连接秘密，供核对使用；不能代替完整备份。

## 卡权益

- 卡权益在独立页面展示，与积分里程分开。
- 只针对信用卡正入账，通过集中维护的关键词规则识别权益。
- 具体权益类型优先于泛化 Credit、Benefit 或 reimbursement 关键词。
- 明确还款词阻止权益识别；通用词还需排除退款、利息、积分兑换等含义。
- 商户 Offer 是普通退款，不是卡权益；编辑选项和权益统计排除 Offer。
- 含 Offer 且无明确还款词的卡退款不因上游转入分类而变成转账或收入。
- 权益使用退款分录及权益类型标记，抵减支出，不另加收入或净资产。
- 分类取该权益配置中首个可用支出分类，否则使用其他支出。
- 只记录返还，不搜索或创建原消费链接；既有链接保留且不在权益界面展示。
- PDF、CSV 导入中的权益识别仅为建议，仍经过审核。
- 页面按卡、年份及简短 Credit / Benefit 类型分组，支持近 12 月统计与逐笔下钻。
- 类型名称从描述或商户中去掉机构、产品、数字和参考号，无有效名称时归为其他权益。
- 统计仅使用有效已确认退款；自动重扫不覆盖所有者编辑、已匹配或上游待审核记录。

## 积分里程

- 积分项目目录与账户分离；所有者从项目列表自行添加账户，同项目可有多个账户。
- 默认不创建积分账户，页面只展示已有账户的项目及相应 CPP。
- 选择已归档项目创建账户时恢复项目，保留其他账户及 CPP 历史。
- 点数使用 BIGINT 整数，事件增减与日终观察共同确定指定日期的点数余额。
- CPP 使用十进制数及生效日期，估值为点数乘 CPP 再除以百分换算系数。
- 积分估值不进入资产、负债、净资产或消费；缺少 CPP 时明确提示。
- 转点保留整笔转点及双方事件，不独立删改一侧而破坏余额关系。
- 删除账户先预览关联数量，执行时加锁复核；数量变化须重新预览。
- 账户删除包含相关整笔转点与双方事件，重新计算对方余额，保留项目目录和 CPP。

## 卡片信息与认证

- 非系统现金或信用卡账户可选保存完整卡号、有效期、CVV，以及 Amex CID。
- 卡号保持字符串并校验 Luhn；公开元数据只包含允许的尾号、卡组织和保存状态。
- 卡片载荷以 AES-256-GCM 加密，通过 HKDF 从 `APP_SECRET` 派生独立用途密钥。
- TOTP、Plaid 令牌与卡片载荷使用不同加密用途，不复用同一上下文。
- 查看卡片必须再次验证并限流：启用 TOTP 时消费新验证码，否则验证当前密码。
- 解密接口禁止缓存；解密值只留在客户端临时查看状态，关闭或 60 秒后清除。
- 敏感卡片字段不进入 URL、浏览器持久存储、服务端页面数据、日志或审计详情。
- 卡片秘密表完全排除个人 JSON、CSV 导出；删除个人数据时同步删除卡片记录。
- 完整备份可以包含卡片密文，恢复依赖原 `APP_SECRET`，必须与备份口令妥善保管。
- 登录采用密码、可选 TOTP、限流和会话 Cookie；写请求校验来源及当前用户。

## 文件导入与 AI

- PDF 默认由本地 parser 提取，扫描件可使用本地 OCR；CSV 支持字段映射。
- 上传后经过账户映射、去重、建议与审核，来源证据和逐行状态保留。
- 上传文件与页面预览保存在私有 `DATA_DIR`，不放入公开静态目录。
- 文件预览和下载按所有者鉴权，保留期清理遵守账单审核状态。
- AI 解析默认关闭，同时需要启用配置及提供方密钥才可用。
- 每份账单必须先展示实际待发送内容、提供方与模型，再由所有者确认。
- 只发送预览中的已遮盖待识别交易行，不直接上传整份原始账单。
- 同意绑定输入内容哈希；预览变化后必须重新确认，不复用旧同意。
- AI 输出须通过结构、金额与来源证据校验，结果仍进入审核流程。

## 隐私与工程约束

- 仓库、种子、测试、截图和文档禁止包含真实财务数据或从真实资料校准的示例。
- `Asset.xlsx` 与 `samples/` 必须保持 gitignored，任何工具都不得打开、遍历或解析它们。
- 合成测试资料由代码生成，使用虚构机构、账户和交易，不从真实文件复制或改名取得。
- 日志仅保留必要标识、哈希和错误种类，不记录账单正文、商户金额组合或认证秘密。
- 卡号、有效期、安全码、会话令牌和提供方访问令牌不得出现在日志中。
- 转账及卡片审计仅记录允许的实体标识；删除审计的计数遵循白名单。
- 金额和汇率计算使用 Decimal，输入和传输使用十进制字符串，金额列使用 NUMERIC。
- 图表坐标可在展示边界转换为 number，不得回流为财务计算依据。
- 每张表有 UUID 主键和时间戳；业务表携带所有者，查询及关联均校验所有者。
- 领域服务接收数据库句柄，事务与锁保护跨表不变量；测试可使用合成 PGlite 数据库。
- 普通账簿与上传文件不承诺整体加密，部署者负责主机、私有卷和备份的访问控制。
- 个人导出使用明确表清单，排除认证秘密、银行令牌和卡片密文。
- 删除全部个人数据需身份验证与明确确认，先撤销银行连接，保留登录用户及安全设置。
- 数据库迁移随代码维护；删除退休结构前检查是否仍有数据，不能静默丢弃未知记录。
- 对外发布采用 AGPL-3.0-only；本地安装、测试与构建不应意外发布 npm 包。
